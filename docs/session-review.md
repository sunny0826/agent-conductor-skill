# 会话归档复盘

按「归档日」复盘会话时，先确定归档时间，不按最后活动时间。`lody_session_list` 没有 `archivedAt` 字段；用 `updatedAfter` 得到的是活动时间，活动在归档前一天、归档在当天的会话会被漏掉。

## 选取范围

```bash
mise exec -- node tools/archived-sessions.mjs --date 2026-10-21
```

工具读取本机 `~/.lody/logs` 中 `Archived session runtime released` 事件，按 `Asia/Shanghai` 过滤归档日。加 `--json` 输出机器可读结果，`--log-root` 可换日志目录。

- 只覆盖本机日志。其他机器上归档的会话不在本机日志里；用 `lody session list --archived` 的“当日活动 + 当前已归档”代理口径补查，并在索引里标注“归档时间未验证”。
- 归档日志可能因轮转在 gzip 流中间截断；工具保留已读出的行，不因单个文件失败放弃全部结果。
- 在当天 inventory 记录每个会话的归档时间、时间来源和机器；代理口径与真实归档时间分开写。

## 派发消息与角色前缀

比对发送文本前，先用 `lody session show <child> --json --offline` 读 `agentRoleId`，再用 `lody agent-role get <roleId> --json --offline` 读 `promptPrefix`。首条用户消息以该前缀开头是宿主注入的角色配置，不算发送污染；去掉这个已配置前缀后仍与落盘消息不同，才是发送时改写。2026-10-24 复盘据此更正了 10-23 的 11 次误判。

## 证据与验证主体

迁移、改名或清理旧术语的会话，要区分产品称呼与历史证据：历史日志、测量记录和验收回执中的原始环境名、命令与数字应保留，被回改成新称呼的列为问题。交付中的检查由子会话完成时，正文应写执行者与回执，不写成协调者自己核对；协调者只对自己的实测写自验。

## 验收分母与未验证项

验收指令里的目标步数、样本数或期望值不是实测对照值。需要用户或外部设备提供分母时，必须实际读回；未读回只写被测增量并标对照未确认，不计算通过率，也不写验收通过。

设备处于下载／引导模式时，端口在线和日志输出只证明引导程序存在；先确认已退出该模式，再取应用运行证据。采样间隔、端口在线、日志连续等前置指标不能写成“没有丢步／没有失败”。

前次交付标注的未验证项在后续交付中保留，直到取得证据关闭；后续其他检查通过不能吸收尚未关闭的缺口。改动文件数、行数等汇总用 `git diff --stat` 对账，不凭记忆估算。

## MCP 与工具派发

用户要求通过 MCP、API 或会话工具派发时，先读子会话第一条用户消息判断形态：是任务包指针加回执，还是整段任务正文。整段任务正文容易把边界条款和回执要求一起带进消息；`check-dispatch.mjs --message` 会报缺回执和边界违规。2026-10-27 的 `b3c5f708`、`da113c7f` 就是这样被 `84bdccab` 派发的。

消息检查通过也不证明包文件合法：对指针指向的包再跑一次包检查，首行必须有三值类型声明。2026-10-27 的 `writer-power-package.md` 缺声明，而指向它的消息本身是合规指针。任务正文里顺带出现的其他 `.md` 文档路径不算包指针；指针应指向要执行的任务包。

## 笼统验收

用户只回复“验收通过”“没有问题了”时，先对照验收清单：哪些项有用户原话或产物回执，哪些只是被笼统认可。未逐项回报的场景仍列为未验证，不能因为合并、后续 PR 或其他检查通过而消失。2026-10-27 的 `a1e60b91` 在 PR #4／#5 的合并前只收到笼统通过，清单中的捕获、重试、无奖励重打和重启保持没有逐项回报。
