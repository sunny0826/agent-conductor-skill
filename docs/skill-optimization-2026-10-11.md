## 实际验证

- 优化前，新增回归中的缩减计划无法通过旧检查器；此前独立复现也已记录“三场景退出 1、两个固定十场景诊断”。新增状态检查器的测试初始因入口不存在而失败，不能把这个缺文件失败当成历史行为复现。
- `node --test tools/test_skill_contracts.mjs`：**11 个测试通过，0 失败**。测试调用真实 CLI，覆盖计划输入与从会话错误提取的状态样本；它们不是原始 Agent 工具调用的自动重放。
- 源文件变更后、重新打包前，`python3 tools/package_skills.py --check` 退出 1，检测到 agent-conductor.zip 与新增成员不一致。
- 重新运行 `python3 tools/package_skills.py`，然后 `--check`：**52 个包全部通过**；11 个含传递依赖的 zip 实际发生变化。frontmatter、技能引用、归档成员与字节一致性均由此入口核对。
- `git diff --check` 通过。新增脚本不依赖第三方包，源代码文件均少于 500 行。

## 仍需真实执行判断的部分

状态检查只检查声明和证据引用是否齐全，不读取引用、不监控真实写入、不取消 Agent、不识别语义上“11 文件”能否证明“19 文件”，也不判断授权原话是否真实。协调者必须读回证据，核对完整场景及实际停止状态。主观风险分类仍须根据改动审查。

因此本轮证明的是契约一致性和错误状态能被检查器拒绝，尚未证明未来所有模型都会维护状态或遵守禁令。B5 的授权复用规则原本已存在，本轮保留它；未新增部署版本追踪系统或审批流程。已有 README 和其他 docs 改动保留。
