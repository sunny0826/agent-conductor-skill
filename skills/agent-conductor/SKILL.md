# Agent Conductor · Agent 指挥官

按「用户要求 + 模型配置 + 工作说明 → 主 AI → 平台与项目 → 执行动作 → 观察结果 → 判断下一步」组织工作，将判断结果反馈给主 AI。

直接使用下列步骤组织任务与验证结果；解释各层责任或配套技能边界时，读取 [节点与配套边界](references/sources.md)。

## 1. 明确用户要求

从当前消息、约定与项目文件提取目标、限制、交付物及可检查完成条件，按意图定授权档位：

- 解释或调查请求：读证据回答，动作限于只读操作。
- 仅要求审核、评估或对比：交付审核结论；实施、修复与派发须等明确实施指令，不以既有流程惯性补全授权。
- 实施请求分两档推进：
  - **阶段关口模式（默认）**：边界未定或需选型时分阶段推进，保留用户指定关口。
  - **全链路托管模式**：用户明确全流程授权（如“开干”“直接做完”“fix all”）或一次性确认整条清单时，在已授权边界内连续推进隔离、实施、门禁、Draft PR（已授权远端操作时）、并行审查与有限轮返工。常规非阻塞取舍自行拍板并记入**变更与取舍台账（Harvest Packet）**；仅当改变产品目标、公开契约、跨仓边界、引入高后果风险，或必需检查未验证需豁免时才停机询问。
- 部署、删数据、共享分支强推、合并主干及对外发消息先核对明确授权并遵守宿主规则；缺授权时先做独立准备并说明关口。保护凭证、认证与用户改动，用实际理由表达不同意见。

## 2. 调用 agent-conductor-setup 配置模型

需要派发子任务时执行本步（主 AI 独自完成或仅解释原理时跳过）。读取 [agent-conductor-setup](../agent-conductor-setup/SKILL.md) 并按 [目录刷新](../agent-conductor-setup/references/configuration.md#目录刷新唯一定义处两个技能共用) 分页枚举 Lody 机器、配置与角色，读取 `.agent-conductor/models.json` 应用选择；两个技能目录须并排保留。

- 显式组合传 `machineId + agentConfigId + modelId`；角色传 `agentRoleId`（多机绑定时加传 `agentRoleMachineId`）且不传模型覆盖；继承省略模型参数。需在目标机器项目内工作时传 `workContext`；无代理工具时由主 AI 自执行自检查。
- 普通任务建会话映射，用户要求保存时再写入项目配置。解释场景若追加真实环境检查再执行发现。

## 3. 读取工作说明

按宿主指令优先级读取项目规则、现有技能与指南；缺少专门说明时不宣称调用不存在的技能。按 [当前技能读取与采用核验](references/skill-adoption.md) 从本次目录选技能并提取要求，不固定版本或复制长期流程，阶段切换或引用更新时重读；协调者组织全流程，参与者只做已分配阶段且不自行派发。

确认项目规则与 CI 适用检查，按风险阶梯（只升不降）缩放审查与验证：

- **`T0` 机械变更**（纯格式、生成物重算、无语义路径同步）：验证生成物一致性与静态门禁。
- **`T1` 常规可逆变更**：目标功能实测 + `reviewer` 单轮独立审查（事前反证与事后审查开不同会话）。
- **`T2` 高后果表面**（鉴权与信任边界、持久化或迁移、并发与锁、资金计费、公开契约或跨仓接口——触及一行即升 `T2`）：验证真实调用链与表面，并按 [interrogate](../interrogate/SKILL.md) 双席盲审（`reviewer` 首席，第二席选目标机器上已获准、可只读且模型家族不同的角色）。

复用已有验收入口或本轮现有命令，保留未执行项及原因。下列配套技能均按需使用、非强制门，缺失时说明限制继续：

| 需要 | 使用 | 何时使用 | 边界 |
|---|---|---|---|
| 理解机制与归属 | `how` | 解释或改前澄清调用与状态 | 先建源码运行模型；简单问题直接查，不代替验收与修改 |
| 结构设计 | `architect` | 非平凡变更比较接口、归属与分层 | 从调用者推导结构，只做设计不自动实施或强制多模型 |
| 功能验收 | `verify-<app>` / `create-verification-skill` | 复用已有或确需时新建 | 一次性小改、纯解释与只读审查不触发新建 |
| 影响分析 | `blast-radius` | 跨边界疑点 | 用于选择验收路径，不代替 verify |
| 交叉审核 | `interrogate` | 明确要求或需多模型排查盲点 | 普通审核不升多模型，不授权修复或替代实跑 |
| 性能主张 | `benchmark-checklist` | 性能测量与据数字选型 | 核验主张与测量证据 |
| 文字清理 | `unslop` | 撰写或润色文档与报告 | 保留原意、数字与证据强度，不扩改代码 |
| 回归检查 | `tdd` | 要求 TDD 或存在低成本检查路径 | 先证失败再证通过，不实用时用有效替代 |
| 追溯动机 | `why` | 追溯历史设计动机与约束 | 仅在需历史证据时使用，不凭现状猜测（多方案比较见 `architect` 内置 `references/arena.md`） |

## 4. 由主 AI 组织任务

由主 AI 维护待办、选择下一步、调用工具、安排分工并对最终结果负责。多写者协作、用户纠正目标、多轮验收或有实施后审查/验证关口时，按 [任务状态对账](references/task-state.md) 维护唯一记录；关口与回执作为验收项入表，交付前运行 `--complete`。普通单步任务不强制建表。

- 根据依赖拆分任务。只读工作可并行；写同一文件或共享实例须明确唯一写入者并串行协调（协调者也是写入者），交接须先拿旧 owner 停止回执。
- 每次派发前读取 [派发契约](references/dispatch.md)。任务包落盘并首行声明类型；发送前运行 `node <本技能目录>/scripts/dispatch-gate.mjs pre <package.md> <message.md>` 至退出 0，发送原文件并在发送后跑 `post`。实验、重放与用户指定的 MCP 派发均不豁免。
- 冻结后的范围变更标明授权来源，不静默吸收；改变已审方案或引入新契约/链路/交互的增量继承原方案同级独立审查，用户纠正目标时先停旧任务再改包。范围增量、零回执取消/切配置及会话续用细则见 [派发契约](references/dispatch.md#范围增量回执与续用规则)。
- 目标交付、撤销或被取代后取消等待中的异步操作，同目标同版本重复回执合并记一次；用户新消息与子任务回执同时到达时先答用户再报回执。
- 完成声明绑定最终回执并标明验证主体（progress 流只作进行中汇报）。独立审查与验证轮次须开零历史污染的新会话；仅同一返工循环修复轮（`h1..h3`）或必要现场延续时续用。
- 使用 setup 核对后的入口和角色选择，只传宿主接受的参数；本地已有 Agent CLI 但无适配器时只记为发现项。协调者亲自读回子任务产物、diff 与证据再总结。
- 任务包按 [采用核验契约](references/skill-adoption.md) 列出适用技能与应回传证据（不硬编码版本）；执行者按当前目录执行并回传原始证据，协调者在 `skill_review` 收口。

### 并行分片与竞赛

覆盖矩阵、并行检查或同题竞赛按 Frame → Fan-out → Aggregate → Report 推进：

- 固定完成条件、切片或竞赛臂边界及产物契约；竞赛须在派发前声明 `first pass`、`rank all` 或 `best-of` 规则，不能见结果后改规则。
- 各写者使用独立目录或 worktree 隔离写入；度量和验收任务固定版本、样本、次数与方法；证据共享时避免把其他工作者答案传给首轮竞赛。
- 只针对真实活动句柄等待并收敛终态，失败、退出或超时须保留为缺片/缺口，不能记作零问题；覆盖模式须每个必需切片均有结果才完整；同模型多会话不算跨模型。

## 5. 核对平台与项目条件

| 层 | 核对内容 | 缺条件时的处理 |
|---|---|---|
| 平台 | 文件读写、命令、子任务、应用控制、定时或事件唤醒是否可用 | 用能证明同一行为的现有工具；无法替代时说明缺项 |
| 项目 | 工作目录、启动命令、依赖、环境变量名（不输出秘密值）、数据、账号与隔离 | 按授权修复基础条件，或记录可复现阻塞；独立工作继续 |

持续唤醒依赖宿主实际定时/事件/后台能力，不以一次性执行冒充。关键路径异步结果未回时，已授权持续推进则在回合内跟进到可判定状态；交还回合时说明恢复条件。

## 6. 执行具体动作

确认工作目录、目标文件、实例和授权后执行最小有效动作：按约定改码/运行、复用真实路径与稳定定位（不绕过待证行为）、隔离并行实例，并在清理后保留证明材料。

日常验收由主 AI 选定受影响功能与入口，verifier 读项目 verify 技能后执行（无委派能力时由主 AI 自验），回传功能 ID、入口、命令、退出码、结果、清理后证据及未执行项。整合后由协调者跑齐第 3 步全部适用检查（含依赖生成物），后续改动使依据失效时重验受影响部分。

## 7. 观察实际结果

直接读回实际产物并与第 1 步完成条件对照：命令看退出码与输出、界面走用户路径、数据读回真实副作用；工具成功、编译通过与代理自述各自只证明可见部分。失败先查观察方法、实例与输入。未执行项写明未验证，推断标为推断，性能数字附运行次数、波动与限制。跑通单个 verify 功能仅证明该场景可用，reviewer 差异审查不能替代 verifier 实跑。

## 8. 判断下一步并反馈

| 状态 | 判断条件 | 后续动作 |
|---|---|---|
| 继续 | 还有未完成步骤，证据支持下一动作 | 更新待办，执行下一单元 |
| 返工 | 经证实的偏离或 `E0`/`E1` 阻塞（`E0` 实跑失败；`E1` 闭合源码因果链） | 触及范围内同类问题全量修复并重验回归；`E2`/`E3` 未实证前仅记录不空转。**硬熔断**：最多 **3 轮（`h1..h3`）**，未收敛或遇冲突则停补丁报阻塞证据 |
| 交付 | 必需完成条件均有相应证据 | 交付结果、证据和必要限制 |
| 受阻 | 缺授权、能力、环境或关键输入，当前无法补齐 | 保存现场，指出缺项、已尝试动作和恢复条件 |

不通过降低完成标准结束循环；用户要求停止时及时止写停子任务并报告状态。

## 9. 交付可核对的结论

简短说明完成了什么、实际验证了什么、证据在哪里、还有哪些缺口或关口，链接实际产物。全链路托管或含自主取舍的任务附精简**变更与取舍台账（Harvest Packet）**，列出非阻塞取舍、方案差异与授权来源及 `E2`/`E3` 记录。

按用户目标逐条对账（预期、实测场景与结果、回执或证据、验证主体），整体测试或自审不替代未覆项；用户笼统确认、目视确认原话及未执行项按 [任务状态对账](references/task-state.md#更新时机与字段) 口径记录，使用任务表时交付前运行 `--complete`。解释链路时写清各层责任及失败位置，区分已完成、未验证与受阻。
