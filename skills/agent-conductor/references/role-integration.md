# 把技能接入角色

角色保留职责、权限与优先入口；技能继续作为流程的权威来源。使用 [共用规则与职责入口](../assets/role-skill-instructions.json) 给已有角色追加一个具名段落，不替换整份提示词，不修改模型、机器、权限或派发确认规则。后续调整只更新同名段落，避免重复追加。

对应职责：`coordinator` 用于协调者，`architect` 用于架构师，`worker` 用于实施或验证角色，`reviewer` 用于代码审查，`challenger` 用于方案反证，`cross_reviewer` 用于跨模型审查参与者，`writer` 用于文档角色。显示名称、机器和角色 ID 来自当次宿主目录，不写入模板，也不把这些职责键当成宿主已存在的角色。

## 角色增减时重新核对

每次整合或角色目录变动时，先按 [setup](../../agent-conductor-setup/SKILL.md) 完整枚举当前目录，直到没有后续分页；同步中的目录不能作为角色已删除的依据。逐个读取当前角色的完整提示词，按实际职责匹配入口，不沿用上次的角色数量、显示名称或待保存卡片。

用稳定 ID 对照上次记录，区分新增、移除、职责变化和规则缺失。同职责可以对应多台机器上的多个角色，每个当前 ID 都要单独检查；仅改名不另建角色。新增职责没有合适入口时先分析其任务和边界，不默认归入 worker。已移除的 ID 不再生成提案。

形成覆盖清单：每个当前角色记录职责、原规则状态、本次差异，以及无需修改、待保存、已读回一致或受阻的结果。没有变化的不重复提交；已有具名段落只替换该段，不叠加旧规则。提交提案前再次读回，若职责或提示词已变，按新内容重做差异，避免覆盖并发修改。

保存后重新枚举并核对当前 ID 集合，再逐个读回确认内容。期间新增或改变职责的角色重新评估，不能沿用旧分母宣称全覆盖。覆盖检查只证明角色配置已接入；技能是否真正采用仍按 [采用核验](skill-adoption.md) 检查实际任务证据，不能把已保存提示词计作已采用。

## 应用与验收

优先入口只是选择线索，实际触发与步骤每次从当前技能读取；新增、改名或移除的技能回到当前目录判断。规则强调 [采用核验](skill-adoption.md)，不预先复制每个技能的全部验收步骤。

应用前读回角色完整提示词，保留原有内容，只修改请求范围。按当前宿主接口操作；Lody 的 `lody_agent_role_update` 仅生成审核卡片，用户点击 Save 后才生效，不能把提案回执写成已更新。保存后读回核对，未保存的保持 pending。已有会话是否重载角色由宿主决定，不假定修改会改变已运行的会话。

技能源先修改并验证，再按已有部署授权同步安装副本；未发布的工作树和未保存的角色提案分别报告。不要为让角色提案立即通过而手工覆盖安装副本，或擅自提交、推送、发布。角色读取不到新增契约时要报告缺口，按共用规则提供已有证据，不能虚报检查通过。
