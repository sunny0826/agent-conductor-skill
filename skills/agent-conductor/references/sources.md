# 节点与配套边界

解释各层责任时按下表对照。执行任务时以 [SKILL.md](../SKILL.md) 的步骤为准。

## 节点与执行步骤

| 层 | SKILL 对应步骤 |
|---|---|
| 你的要求 | 1. 明确用户要求 |
| 模型配置 | 2. 调用 agent-conductor-setup 配置模型 |
| 插件里的说明 | 3. 读取工作说明 |
| 负责这次任务的 AI | 4. 由主 AI 组织任务 |
| 运行平台 | 5. 核对平台与项目条件 |
| 你的项目 | 5. 核对平台与项目条件 |
| 执行具体动作 | 6. 执行具体动作 |
| 读取实际结果 | 7. 观察实际结果 |
| 决定下一步 | 8. 判断并反馈，9. 交付结论 |

## 适配边界

- 配套 [agent-conductor-setup](../../agent-conductor-setup/SKILL.md) 以 Lody 为主分页发现模型；本地扫描仅在 Lody 不可用时兜底，并说明范围不完整。读取项目 `.agent-conductor/models.json` 并核对当前宿主派发能力。两个技能目录须并排保留。
- 两个技能均不读取 Cursor 配置、缓存或接口；使用宿主实际可用的 Agent、provider、模型和持续运行能力。
- 发现 CLI、Agent 定义、配置模型和模型目录不等于当前可调用；宿主禁用模型选择时继承默认，普通任务仅在会话应用映射，明确要求保存时才写入项目配置。
- 按当前用户授权和宿主规则执行。明确发送消息的授权，保留不可逆动作的必要关口。
- 本技能覆盖上表的责任分层和反馈循环。领域操作读取项目已有技能及规则。
- 验收：先复用已有 verify，必要时才用 [create-verification-skill](../../create-verification-skill/SKILL.md) 生成。日常由 verifier 运行 verify 并回传功能/入口证据，conductor 判断交付，reviewer 审查不能替代实跑。生成器的 ZIP 只含它自己的链接闭包，不依赖模型发现或 setup 协议。
- 影响分析：[blast-radius](../../blast-radius/SKILL.md) 保留间接消费链和真实代码证明，独立使用不依赖模型扫描；证据用于选择后续验收，不成为强制门。
- 多模型审核：[interrogate](../../interrogate/SKILL.md) 仅在明确要求或具体任务需要时调用；普通审核不升级为强制多模型门，setup 配置协议保持不变。独立发现与主审裁决不替代影响证明或功能验收。
- 性能核验：[benchmark-checklist](../../benchmark-checklist/SKILL.md) 仅在测量、报告性能或据数字选型时使用；独立核验主张，不依赖模型发现，不引入自动优化循环。
- 机制解释：[how](../../how/SKILL.md) 保留源码追踪、按复杂度分工与解释汇总；简单问题由主 AI 完成，不依赖模型扫描，不代替影响证明或功能验收。该技能的 ZIP 只含其链接闭包，成员由打包工具按正文链接计算。
- 结构设计：[architect](../../architect/SKILL.md) 保留现状取证、调用者优先、结构比较与推翻重做；必要规则自包含，额外技能按需使用，不强制多模型或实施。该技能的 ZIP 只含其链接闭包，成员由打包工具按正文链接计算。完整包内依赖见 [arena](../../arena/SKILL.md)、[why](../../why/SKILL.md) 与 [原则索引](../../architect/references/principles.md)。无需安装外部 SKILL，工具与运行权限仍以宿主为准。
- 回归修复：[tdd](../../tdd/SKILL.md) 保持先失败再通过和测试不可行时的有效替代规则，独立使用不依赖其他 SKILL。
- 写作润色：[unslop](../../unslop/SKILL.md) 保留稳定规则 ID 并适配中文，不依赖外部写作技能，不改变事实和证据强度。
