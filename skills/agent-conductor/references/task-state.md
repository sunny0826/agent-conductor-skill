# 任务状态对账

用于多写者协作、用户纠正目标或多轮验收。真机或设备验收、发布、部署等有多轮验收的任务必须建表，交付声明前运行 `--complete`；普通单步任务不强制。复用项目已有任务记录，字段足够时导出相同 JSON 即可；否则从 [模板](../assets/task-state.json) 复制到本轮证据目录，不再维护另一份含义不同的计划。协调者是唯一更新者，子任务回传结果；不要求提交记录或保存到外部。

## 更新时机与字段

- 派发前：`goals` 记录当前用户要求的来源 `source`，验收项 `acceptance` 记录完整场景与 `expected`。Agent 提议不能写成用户原话，独立审查与用户指定关口各自保留验收项。`tasks` 绑定目标、实际 owner、工作区、写入路径和禁止事项，包含协调者自己的写入。
- 同一物理 checkout 使用同一 `workspace`；独立 worktree 使用不同标识。`writes` 填相对工作区的文件或目录，统一正斜线、实际大小写，无 glob、别名、`.` 或 `..`；目录涵盖后代，跨仓库或符号链接先解析实际归属。它是声明检查，不是文件锁。
- 用户纠正目标：保留旧目标，标 `superseded`，新目标使用新 id；先停止旧任务，收到实际停止回执才标 `stopped`，回执放 `evidence`。未停的任务保持原状态，检查失败暴露待处理项。已完成的历史任务保持 `done`，不冒充新目标结果。
- 写入交接：旧任务停止或完成并附回执，再启动新任务。其他写者仍占用的文件由其修改，协调者不能边集成边替它实现。同一 owner 的两个并发任务同样不得重叠。
- 验收返回：每项分别记录 `observed` 与证据路径／会话引用；只有证据支持该项完整 `expected` 时才标 `passed`。用户笼统回复「验收通过」「没有问题了」不等于清单逐项通过；清单中没有对应原话或产物回执的项保持 `pending`。小样本通过只记录到对应小样本项，完整路径仍为 `pending` 或 `blocked`；不要把 19 文件目标原地改成已测的 11 文件。必要范围变更回到用户授权与目标更新，不用删除失败项让检查变绿。`observed` 写「用户确认」「目视确认」时必须附用户原话；串口、日志、截图和测试退出码只能记为设备或产物证据。笼统通过不得扩写成具体项通过，此前明确未执行的检查保持 `pending` 或 `blocked`。

## 检查入口

技能采用按 [当前技能读取与采用核验](skill-adoption.md) 在 `tasks[].skill_review` 记录候选选择、当前来源的读取证据、本次要求及核验结果。模板的空目录证据和选择理由须在开工前填实。要求来自本次读取内容，不固定技能版本；角色只记录自己承担阶段的要求，跨角色部分由协调者安排。

派发、目标变更、所有权交接后运行：

```sh
mise exec -- node <agent-conductor目录>/scripts/check-task-state.mjs <task-state.json>
```

准备宣称任务完成时加 `--complete`。普通检查允许诚实记录待验或受阻项；完成检查要求活动目标每项有实际结果及证据，且所有任务已终结。失败时继续处理或交付标明缺口的阶段报告，不因此自动要求额外审批。

`--complete` 还要求活动目标中未取消的任务都有技能选择核对；必需技能已读取、当前内容已确认，所有适用要求均有执行与核验依据。仅有名称、读取、自述执行或未核验的产物不能通过。没有匹配技能也须记录目录、判断主体和原因。旧记录缺 `skill_review` 时仍可做普通检查，但当前目标完成前须补齐；已被取代目标和已停止任务不追溯增加采用义务。记录了采用字段时，无论是否完成模式都检查其结构与内部一致性。

技能检查由包内 [skill-adoption.mjs](../scripts/skill-adoption.mjs) 随原入口执行，拒绝缺读取或核验记录的采用完成声明。它只验证声明结构；是否漏选技能、是否遗漏适用要求、证据是否支持结论仍由协调者对照当前目录及原始记录核验。

检查器拒绝目标引用失效、被取代目标仍有活动任务、同一工作区的运行任务写入路径重叠、缺回执的停止／完成，以及缺证据的验收通过。它不执行证据、不访问引用、不监控实际进程、不判断风险或语义等价；填了引用不证明引用内容真实。协调者仍须读回证据，核对预期、实际场景、版本和用户授权。停止回执与网络限制依赖宿主能力，不能声称本脚本能中止 Agent 或阻断下载。

维护者修改模板、脚本或此契约时，运行仓库 `mise exec -- node --test tools/*.test.mjs`，再运行 `mise exec -- python3 tools/package_skills.py` 与 `mise exec -- python3 tools/package_skills.py --check`，验证行为及下载包一致性。
