# Arena · 独立探索与合成

适用于明确需要多个独立方案比较、或不同解法取舍重大的设计与实现。交付一个有来源的基础方案与合成结果，不进行多数投票或机械混合。

协调者在既有派发授权内组织下列六阶段；候选和评判只完成各自阶段，不自行创建其他 Agent。参与者回传实际产物及证据，由协调者核验整体阶段是否完整。

## 1. Frame：固定共同问题

明确用户目标、边界、事实包、允许写入的位置与候选产物契约。协调者先拟定 3–6 条可检验的评分标准，标准暂不发给候选，避免迎合评分。所有候选收到相同问题、事实与产物要求，各自产出完整方案、理由、假设和一个被拒绝的替代方案。

读取实际委派工具说明与既有角色配置；配置确实缺失时用包内 [setup](../../agent-conductor-setup/SKILL.md)，不硬编码模型或启动未经授权的 Agent CLI。至少两个独立会话，首轮不可看其他候选。不同模型有助于多样性，但实际模型身份必须可核对；同一模型的不同独立会话不是跨模型试验。没有委派能力时可交付主会话草案，但须明确 Arena 独立探索未完成。

## 2. Fan-out：独立产出

每个写者使用独立文件、临时目录或隔离 worktree；按 [设计原则](principles.md) 分离共享写目标，不并发改写同一文件。设计任务不改产品。候选失败或超时记录为退出，不能视为支持其他候选；不足两个有效候选则不宣称完整比较。

## 3. Cross-judge：候选完成后独立评判

所有候选完成并停止写入后，给只读评判者完整、以中性标签标识的候选和评分标准。优先使用实际可用的不同模型家族，复用宿主选择；不得伪造身份。评判者不参与候选编写，逐项比较并引用原文位置。协调者同时阅读全部原始产物，不只读摘要。缺少独立评判则报告该阶段未完成，不能用自评冒充。

## 4. Pick：选择一个基础

协调者按标准核对假设与证据，结合独立评判选一个完整基础。相近时优先可维护、公共接口较小的形状。记录与评判意见一致／分歧及其原因；意见数不是事实证明。

## 5. Graft：有依据地吸收

逐个检查未选方案，吸收一两个与基础结构一致的有用部分，说明来源及其收益，也记录拒绝项。已经收敛可不吸收，须说明。相互矛盾的状态归属、接口或假设不能混合；分歧揭示任务定义错误时先重定问题。结合 [设计原则](principles.md) 控制复杂度并避免强行打补丁。

## 6. Verify：核验真实结果

检查最终产物而非投票结果：实现须走真实行为，设计须核对源码、调用者与约束，并明确未实施。验证失败先判断共同问题错误还是缺少必要吸收，不能靠保护分支掩盖。需要审计轨迹时保留阶段、决定、原因、证据与结果记录（提交沿用既有授权）。

交付合成产物、基础／吸收／拒绝来源、候选退出情况、独立性与模型身份、验证证据和剩余缺口。
