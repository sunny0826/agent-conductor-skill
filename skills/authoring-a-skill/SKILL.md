# 编写或修改技能

先确定真实请求、触发范围、完成产物和权限。创建具名目录与 SKILL.md，YAML 至少有 name、description，name 用小写 kebab-case，description 说明能力与辨别触发，不抢占无关任务。复用用户指定或宿主确认的项目位置，不默认全局。

正文只保留能改变执行决定的信息；相关细节按需放 references，可复跑逻辑才用 scripts，产物模板才用 assets。没有用途不建 README、空路由或额外脚本。执行所需的依赖用包内路径明确连接，不仅写名字。可选引用只写技能名和“若已安装”，不写 Markdown 链接，因为打包工具把每条链接都当作硬依赖并带上它的全部传递闭包。没有对应目标就不假装调用宿主内置 create-skill。

按 [unslop](../unslop/SKILL.md) 清理表达，保留用户风格和所有必要约束。默认正常自动选择，明确请求仅手动调用时才设置该政策；无审批权不意味着改成手动调用。

核对 frontmatter、UI 元数据、引用、全部传递依赖与归档；新增脚本实际执行。结构／风险复杂时用未提示预期答案的隔离真实请求评测，主观风格用用户反馈，不虚构 benchmark。仅格式检查不能证明好决策。

交付技能路径、决定、验证与缺口，已有授权才提交或开 PR。
