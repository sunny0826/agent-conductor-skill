# 提取个人工作方式

产物是一个以用户选定标识命名的 <handle>-mode 技能。只提取其工作约定，不复制上游作者风格。

1. 在宿主实际支持且已授权的项目技能位置查已有匹配技能，包括项目的个人分类目录。用户已说更新则就地更新；否则只在“更新还是新建”会改变结果时澄清。更新保留未被反证的章节，按实际版本记录只调查上次修改后的证据。
2. 只检索宿主明确提供的本工作区会话接口／路径。大范围可按时间片并行只读调查，小范围直接读。对话缺失就用用户明确偏好，不扫描其他项目。收集回复风格、委派、验收、代码与文字、交付和元流程，证据至少跨两个片段反复出现才将推断当稳定习惯；用户明确偏好无需伪造重复。
3. 一到两个简短问题补足会改变规则的未知偏好，优先易选选项，再允许遗漏项自由补充；已有答案不反复问，不一次给几十题。
4. 按实际证据分组：回复、自主性、理解现状、委派、代码、验收或交付。没有特殊规则就不建空章节。参考包内 [rigor](../rigor/SKILL.md) 的粒度，不复制其内容。相互矛盾的信号保留待定，不自行替用户决定。
5. 用包内 [编写技能流程](../rigor/playbooks/authoring-a-skill.md) 起草／修改，保留既有路径；新路径从宿主事实确定，不默认 Cursor 或全局目录。name 使用 kebab-case；description 针对名字、mode 和该用户风格，不抢占所有“写代码／审核”。自动选择按用户意图及宿主支持设置，不以缺权限代替明确调用政策。
6. 用 [unslop](../unslop/SKILL.md) 清理表达，其他依赖用实际包内路径引用，不能复制不属于该用户的偏好。交付草稿并按用户反馈迭代，主观风格以用户评价为准，不虚构量化 benchmark。仅触发准确性真实有问题时再优化描述。

用户只要一个任务流程或窄主题时直接编写普通技能，不做习惯挖掘。没有授权不修改全局技能、提交、推送或开 PR。
