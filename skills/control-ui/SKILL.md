# Control UI · 驱动界面并交付截图

先复用项目已有 Playwright、浏览器／Electron harness 或宿主应用控制工具；没有现成 harness 时，使用当前已安装工具建立本次临时探针。该技能提供操作指导，不安装浏览器、不注册 MCP，也不使宿主自动获得控制能力。

## 选择实际可用的入口

1. 读取项目启动与验收说明，确认目标版本、实例归属、URL／窗口、测试数据和就绪信号。只驱动本次拥有或明确授权的实例。
2. 有项目验收工具就沿用；宿主提供浏览器／应用控制时，先读当前工具说明，使用其真实截图与保存接口，不猜 API。Web／Electron 缺此入口但已有 Playwright 时，按 [可运行示例](references/playwright.md) 创建临时脚本。
3. Electron／Chromium 仅在项目支持且已授权的调试实例上连接 CDP；原生桌面／移动应用使用实际应用控制、模拟器或设备驱动，不能拿浏览器页面代替原生窗口。
4. 核对工具、浏览器可执行文件及截图能力。缺能力时列出缺项和可恢复条件，不自动下载依赖，不转去读取特定编辑器私有配置，不以旧截图称本轮通过。

## 驱动与截图

- 按应用标识、窗口标题、URL 和稳定根节点共同确认目标。多个候选时先消除歧义，不能默认第一个标签页。
- 先观察最新页面结构或截图，再用角色、可访问名称、稳定属性定位；坐标操作须有刚取得的截图。结构变化后重新观察，不复用陈旧元素引用。
- 保存操作前截图，执行一个真实用户动作，等待明确可观察的状态，再保存操作后截图。多步交互按关键状态重复；不要用固定睡眠冒充就绪，也不要直接改 DOM／内部存储来制造结果。
- 截图保留足以识别应用和功能的上下文，并展示目标状态。需要局部细节时补局部图；整页截图不能证明屏外内容实际可见。避免捕获密钥、个人数据或无关窗口。
- 原型比较分别截图各变体；视觉一致性比较使用相同尺寸、数据和状态，保留图像差异证据，不能凭截图存在就宣称像素一致。

## 读回与交付

截图保存到本次独立的证据目录，按 PR／场景／状态命名，例如 `<artifact-root>/<pr-id>/<scenario>-before.png`、`<scenario>-after.png`。临时运行状态与证据分开存放。

使用宿主图片查看工具或已有图像工具重新打开实际文件，确认可解码、不是空白／加载页、目标应用与预期状态可辨认。文件存在或命令成功不足以完成截图验收；没有读图能力就明确标为“已捕获，未视觉核对”。

交付每组截图的真实路径、目标版本、场景、动作、捕获时间、预期与观察结果。宿主支持时嵌入图片，否则提供可点击的实际路径或已授权链接，并简述图中变化。跨机器路径不等于用户可访问：使用已有授权的附件传输／共享位置，读回可访问性；没有交付通道则报告未交付，不虚构链接或自行上传外部服务。

截图只证明拍到的状态；异步完成或持久化等行为仍需对应的真实读回证据。遵守已有人工审核关口，截图交付不授予合并或发布权限。

无论成功或失败，清理本次创建的浏览器、连接、服务及临时数据；不关闭用户已有应用或删除证据。清理后再确认截图仍可读取。
