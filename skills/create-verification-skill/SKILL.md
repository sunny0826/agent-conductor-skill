# Create Verification Skill · 项目验收技能生成器

为接手项目的 Agent 编写可直接执行的验收说明。产物是项目内的 `verify-<app>/SKILL.md` 和功能地图；日常验收使用该产物。本技能可独立使用，不要求扫描模型或调用 conductor。模型与角色配置仍由包内 [agent-conductor-setup](../agent-conductor-setup/SKILL.md) 负责，不在此建立配置协议。

## 1. 读取项目事实并确定落点

先找已有 verify 技能、验收流程及 harness。已有匹配能力时复用；需要补充时在授权范围内更新，避免生成重复入口。只读请求不写文件、不启动实例。

从仓库规则、文档、脚本、路由、命令和测试核对：

- 用户表面：Web、CLI/TUI、桌面、API、移动端或库；确定主要入口并列出其余入口。
- 启动：实际命令、运行时、依赖、就绪信号、端口、环境变量名称、数据与认证前置条件。不要输出凭据。
- 驱动与观察：优先项目已有 harness，使用真实命令、路由、ARIA 名称或稳定属性；明确输出、截图、日志、退出码和副作用的读取方式。
- 隔离：端口、数据目录、账号、设备或配置是否可独立；无法隔离时指定唯一驱动者，不能并发操作共享实例。

优先采用项目现有且当前宿主确实能发现的技能位置；没有约定时，核对当前宿主文档或配置，使用其明确支持的项目级位置。不要把 `.cursor/skills` 当作跨宿主默认，也不要把 `.agent-conductor` 配置目录当作技能发现位置。宿主无自动发现能力时，可保存到项目约定路径并说明通过文件引用使用，不声称已自动注册。不修改全局技能或宿主设置。

启动失败时先在已有授权内修复条件；无法修复则保留失败命令与原因，交付明确标为草稿/受阻的说明及缺口。不要编造尚未确认的命令、选择器或成功记录。必要的验证脚手架须标明用途，并纳入本次清理范围。

## 2. 编写 verify 技能与功能地图

`SKILL.md` 使用 YAML frontmatter，`name` 为实际的 `verify-<app>` 名称，`description` 说明应用、操作表面及适用任务。生成内容必须来自项目事实，不能直接复制示例命令。正文包含：

| 部分 | 必须能执行的内容 |
|---|---|
| 启动与就绪 | 工作目录、前置条件、精确命令和有界就绪检查；短命 CLI 每次调用独立进程，无需常驻服务 |
| 健康与身份检查 | 只读确认进程/可执行文件、版本或构建、实例归属、数据目录及所需认证；异常时先检查，不能误驱动别人的实例 |
| 驱动 | 真实用户路径、稳定定位、输入与可观察预期；不以内部 setter 或测试专用接口代替用户行为 |
| 证据 | 功能 ID、入口、命令/动作、输入、输出、退出码、结果和副作用读回；记录版本与运行范围，证据存放在独立于临时状态的位置 |
| 清理 | 成功和失败都清理本次启动的进程/实例和临时状态，按记录的归属清理，不按进程名称批量终止；证据保留并在清理后读回 |
| 必要脚本 | 仅在有实际复用价值时添加，正文给出用法、参数和依赖，实际运行验证；需直接执行的脚本设置可执行权限 |

创建 `features/README.md` 索引和每个已识别功能的说明。优先覆盖主要 3–5 项，项目更小时按实际数量；明确地图尚未覆盖的表面。每项记录功能 ID、所有已知用户入口、前置条件、动作与预期结果、证据和陷阱。需要结构示例时读取 [最小功能地图示例](references/feature-map-example.md)。地图有多个入口时，验证一个入口不能代表其他入口通过。

外部发送、删除、发布、账号操作等沿用用户已有授权和宿主规则，生成技能不扩大授权。使用 dry-run 或测试模式时，观察其实际跳过的文件、网络或其他副作用；不能仅凭名称认定无副作用。仅在已有生产边界隔离外部系统时使用 mock，并注明覆盖限制。

## 3. 实跑生成说明

按生成的说明完成一次「启动 → 就绪及身份检查 → 驱动至少一个已映射功能 → 取证 → 清理 → 读回证据」。失败后也执行清理，修正有证据支持的问题，再重跑受影响步骤。

将每个功能及入口分别记为已验证、失败、受阻或未执行。未映射、未执行、跳过的功能不算完成。只有实跑和清理后证据检查均成功，才能报告生成说明已验证；这只证明本次场景可用，不等于整体验收。缺少运行条件时报告草稿/受阻和恢复条件。

## 4. 交付与后续使用

交付生成路径、宿主发现依据或文件引用方式、功能地图范围、运行命令与退出状态、保留的证据位置及未验证项。conductor 按任务选取受影响功能，verifier 使用 verify 技能回传证据；reviewer 的差异审查不能替代实际运行。

项目入口、命令或行为变化时，在同一 verify 技能与地图中修订对应项，重跑受影响路径并保留证据；不依赖另一个维护技能。来源与改编说明见 [来源映射](references/sources.md)，沿用 [MIT 许可及署名](LICENSE)。
