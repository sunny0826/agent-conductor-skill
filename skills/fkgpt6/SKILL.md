# 排查项目冗余与过度防御

本技能面向“长期迭代把发版级审计、推测性守卫和脆性锁定前移到日常开发热循环”的工程减负。目标不是盲目删检查，而是以实测数据区分真实边界与无效内耗，在授权范围内分波拆除并验证未破坏真约束。

## 适用边界

- **纳入**：开发热循环与强行哈希、静态门禁范围与噪声、测试分层与耗时瓶颈、CI 触发与发布仪式、打包分发与仓库卫生、文档/规则与测试或打包的“隐形锁”。具体清单见 [排查维度与裁决清单](references/audit-checklist.md)。
- **不纳入**：局部代码与注释、workaround 清理（用 `rigor` 代码检查；若源码哈希锁阻断清理，先用本技能拆锁）；防御性 UI 文案清理（若已安装，用 `clean-ui-copy`）与界面交互审计；单次 diff 的局部代码精简（用 `rigor` 代码检查）；产品功能重构或架构重设计（用 `architect` / `refactoring`）；加约束防重复错误（用 `correct`）。
- **权限边界**：排查与诊断只读；未获用户明确确认不直接大删；不自动 commit、push、合并 PR、发版、删除用户数据或修改全局配置。

## 执行流程

1. **只读盘点与实测基线**
   按 [排查维度与裁决清单](references/audit-checklist.md) 扫描配置、任务脚本、CI 工作流、静态检查、测试套件、构建打包与文档规则。对可运行的检查采集真实基线（单测 vs 集成耗时、慢测 Top 项、静态检查耗时与误报数、近次 CI 耗时、产物/目录/闭包规模）；无法实测的项明确标“未实测”，不凭印象定性或估算提速倍数。

2. **三分法裁决与停等确认**
   输出结构化诊断表（类别 / 具体位置 / 实测代价 / 合理性判断 / 建议裁决与影响），逐项归类：
   - **保留**：真实安全防线、传输或原始证据防篡改校验、跨层架构依赖边界、外部平台/协议硬约束。
   - **后移或分层**：发版级/供应链级审计、多平台打包安装、真机或重型 E2E 从 `dev` 热循环与每次 PR 移至 release、nightly 或显式手动任务；拆分 unit 与 integration；补齐 CI 路径过滤与构建缓存。
   - **拆除**：非证据用途的源码/注释/文档哈希互锁、扫进构建产物的静态规则、零引用死代码与死脚本、入库二进制产物与污染扫描的大目录、锁死过程文档逐字节的脆测试、与代码脱节的僵化仪式。

   **默认停在诊断与裁决表**，列出必须由用户拍板的高影响取舍（如工具保不保留、彻底拆除还是降级、过程文档去留），等确认后再实施。

3. **按 Wave 分批实施**
   获准后按“高收益低风险 → 解耦反向锁定 → 拆除重型机制 → 补齐必要轻门禁”分波推进，遵循先减后加原则。每波保持独立可验证、可回退；涉及架构边界、CI 拓扑、构建或发布链路的高风险波次，在具备独立委派能力时安排独立审查者核对 diff 与未覆盖路径，无独立能力时明确报告仅完成自查。

4. **删后防误删复核（每波必做）**
   - **零断链与悬空引用**：除 Markdown 链接外，核查源码、构建脚本、打包白名单与错误提示中是否残留被删文档/脚本的硬编码路径。
   - **关键入口不丢失**：清理冗余文档后，安装、排错、必填配置格式与真实契约仍有明确权威入口，不出现“文档和提示全删光”或指向无关文档的假路径。
   - **保留红线仍生效**：收窄静态检查范围或放宽阈值后，确认留下的安全/架构边界规则仍能拦截真实违规（必要时用隔离反例验证）。
   - **测试仍验行为**：松绑脆测试后，保留用例仍断言真实结构与行为，不沦为空壳通过。

5. **前后实测对比交付**
   汇报改动项、保留项及理由、防误删复核结果、前后实测对比（耗时、findings、产物/闭包/目录变化）以及未验证范围（如远端 CI、跨平台打包、真机路径）。
