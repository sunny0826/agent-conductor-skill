# 排查维度与裁决清单

本清单服务于工程冗余盘点、三分法裁决与删后复核。实测数据缺失时必须标为“未实测”，不根据源码静态猜测运行耗时。

---

## 一、六大排查维度

### 1. 开发热循环与强行哈希
- **本地开发不可变打包**：`dev` 启动器是否禁用 editable / 增量模式，每次改动都重建完整分发包与隔离环境。
- **编辑期全量哈希校验**：构建前后是否对源码树计算多重 SHA-256，导致 IDE 保存文件即触发校验异常而中断构建。
- **非证据用途的内容哈希锁**：源码或注释 SHA-256 是否绑定到运行状态、历史任务续跑、测试 fixture 或审批产物中，导致改注释或内部重构即阻断流程。
- **内置文件运行时重算哈希**：对随安装包一起分发的静态资源或文档在运行时重复计算并校验摘要。
- **开发期强制摘要引用**：本地联调镜像、本地制品是否硬性要求 `@sha256:...` 而拒绝开发 tag。

### 2. 静态门禁与架构检查
- **扫描范围污染**：`include` / `exclude` 是否把前端/后端编译产物、压缩 bundle、生成代码、测试目录或一次性脚本纳入审计。
- **零容忍与已知误报冲突**：门禁是否要求零 findings 且禁止合理例外，而分析器对框架序列化、反射或模板语法存在成批已知误报。
- **过度机械的尺寸阈值**：单文件行数、函数行数、复杂度或参数数量限制过严，导致为过检而机械拆碎内聚逻辑或制造无意义参数对象。
- **真约束淹没在噪声中**：高价值规则（如跨层 `import` 方向、包所有权边界）是否被大量低价值风格告警掩盖或拖慢到无法日常运行。

### 3. 测试分层与耗时瓶颈
- **隐蔽阻塞与慢测**：单元测试中是否包含未覆写的真实 `sleep`、固定观察等待窗口、子进程风暴或重型磁盘/网络 I/O。
- **测试未分层混跑**：毫秒级 unit test 与分钟级 integration / E2E 混在同一默认串行命令里，阻塞每次本地改动验证。
- **重复矩阵与过度对齐**：多组编译 tag 重复运行全量无关测试，或大量逐帧/UI 快照与内部细节强绑定，导致微调 UI 需多处同步改动。
- **锁死文本的脆测试**：单元测试是否断言非契约提示文案、过程文档或审批稿的逐字节输出。
- **大体积残留目录拖慢扫描**：仓库根目录或源码树内是否堆积大体积构建缓存、历史产物或测试数据，拖慢 `test` / `build` / `vet`。

### 4. CI 触发与发布仪式
- **时机错位**：每次 PR 是否无差别触发三平台打包、安装包静默安装/卸载冒烟、真机 UI 测试或高成本外部模型 E2E。
- **缺少路径过滤与缓存**：工作流未配置 `paths` / `paths-ignore` 导致纯文档 PR 跑满全套构建矩阵；任务运行器（如 `mise` / `Makefile`）缺少依赖缓存或输入输出声明，连跑 `build` / `lint` / `test` 时反复重编前端或底层产物。
- **早期阶段堆砌重型发版仪式**：尚在 `v0.x` 快速迭代期，却要求跨多条流水线手工搬运 SHA / Run ID、双阶段封存与双重签名校验。
- **本地串行替代远端 CI**：缺少最小自动化 CI，却把重型检查与多步骤人工留档全部压在本地同步阻塞执行。

### 5. 打包分发与仓库卫生
- **非确定性二进制入库**：构建脚本未固定时间戳/权限或把几十个二进制压缩包直接提交进 Git，造成仓库历史持续膨胀。
- **参考链接引发依赖闭包爆炸**：打包器把 Markdown 中“相关/可选参考”链接全部纳入传递闭包，导致单技能或单模块附带大量无关依赖。
- **打包成员过滤缺失**：发布归档混入 `__pycache__`、`*.pyc`、`.DS_Store` 或测试文件。
- **公开边界与个人环境耦合**：公开仓库出现本机绝对路径、私有项目名、会话标识、个人账号角色名，或将个人本地工具链写死为唯一入口。
- **孤儿与死资产滞留**：零调用方的私有审计工具、历史一次性脚本、过期静态台账长期滞留公开工具目录。

### 6. 文档与规则“隐形锁”
- **过程文档反向绑架测试/打包**：一次性审查长文或安装说明被写死在单测逐字节断言、`sdist` 必含白名单或 `dev` 脏检查输入列表里；长文超过预提交 token/体积上限无法常规编辑。
- **规则文件堆砌僵化仪式**：项目协作指南（如 `AGENTS.md`、贡献指南）堆满“零容忍”“逐次双处手工核对”等过时条目，与代码现实和当前工具链脱节。
- **同主题文档多份镜像打架**：同一架构或部署说明在多处复制粘贴，维护时只改一处导致互相矛盾。

> 注：产品界面中的防御性免责文案清理使用 `clean-ui-copy`，UI 交互/组件规范审计归前端评审技能，均不在此维度展开。

## 二、三分法裁决速查表

| 裁决级别 | 判断标准 | 典型处理方式 | 常见误判提醒 |
| --- | --- | --- | --- |
| **保留** | 直接守卫外部安全、真实数据完整性、不可逆边界或跨层架构依赖 | 保留检查并收敛到正确边界；若运行过慢，仅做局部缓存或范围裁剪而不降级语义 | 不能把“包内原始证据封存校验”“跨层循环依赖检查”当作冗余哈希或冗余门禁一并拆掉 |
| **后移或分层** | 检查本身有真实价值，但触发频率或执行位置放错了（发版级塞进 `dev`/PR） | 从 `dev` 热循环与 PR 移至 release / nightly / 手动触发；拆出快速 `test:unit` 与独立 `test:e2e`；补 CI `paths` 过滤与缓存 | 后移不等于删除，需在交付中写明新的触发入口与周期 |
| **拆除** | 不守卫真实用户/系统风险，只锁死内部实现、文档字节、静态历史或制造持续误报内耗 | 删除死脚本与入库二进制、解除源码/文档反向哈希锁、排除编译产物误扫、放宽不合理硬阈值、清理过时过程文档与脱敏 | 拆除前核对是否有外部脚本、CI 或打包器直接引用该路径 |

## 三、删后防误删复核清单

每完成一个 Wave 的清理，必须逐项核对后再推进下一波或交付：

1. **全仓路径与引用扫描**
   - 不仅检查 Markdown 链接，还要全文检索代码、构建脚本、CI 配置、打包白名单与错误提示，确认没有残留已删除或移动文件的硬编码路径。
2. **权威入口与最小可用指引仍在**
   - 精简文档或报错提示后，确认安装、配置字段示例、排错命令与真实契约仍有明确入口；不得出现“文档删光、代码指向的相对路径却无对应内容”的假指引。
3. **保留边界真实有效（反例验证）**
   - 修改静态规则的 `include`/`exclude`、调整门禁阈值或重写检查脚本后，必须实跑全量检查确认 `0` 误报；对保留下来的高价值规则（如禁止逆向跨层依赖），必要时用隔离反例确认违规仍会被拦截。
4. **测试仍验证真实行为**
   - 松绑脆性测试或删除重复矩阵后，核对剩余用例仍覆盖核心结构、边界输入与失败路径，而非只剩永远通过的空壳断言。
5. **前后实测可追溯**
   - 用同一命令对比清理前后的耗时、findings 数量、测试包耗时与产物/闭包规模；未能实际运行的远端或跨平台路径如实列入未验证范围。
