# Interrogate · 多模型交叉审核

交付有证据的审核结论。审核对象保持只读，不自动修产品、改配置、提交、推送、开 PR 或发消息。

## 固定范围与意图

从用户请求和项目事实确定目标、约束及可核验完成条件；仅询问无法查明且会实质改变判断的信息。核对实际基线、HEAD、工作树、暂存区及相关新增文件，不假设主分支名称，不遗漏未提交内容。

固定审核快照：保存相关 diff、文件及追踪调用链所需上下文，记录路径、版本和内容指纹。证据包限于任务所需，排除秘密、无关文件和其他会话内容。审核期间相关内容发生变化时，说明结论属于旧快照，按变化范围复核，不直接合并不同版本的发现。

## 确认模型与独立派发

复用宿主明确提供或用户已选定的模型能力。确需选择时使用包内 [agent-conductor-setup](../agent-conductor-setup/SKILL.md) 作为目录与配置来源，遵守已有选择和预算；缺失时说明限制。当前 setup v2 仅有单 reviewer 映射，不虚构 reviewers 字段、不修改 schema；本轮名单可保存在会话内。角色派发只传 agentRoleId，不手动覆盖 model。

不硬编码模型、数量或推理档位。确认实际模型身份，以不同模型的新独立会话进行交叉审核；不同人设不代表模型多样性。将同一任务、快照、完成条件和判定标准交给所有审阅者，首轮不共享彼此发现。派发时读取并填入 [统一审核请求](references/reviewer-prompt.md)。

记录每位审阅者的实际模型、角色（若有）、会话标识、成功／失败／缺失状态及原始报告位置。成功零发现是合法结果；失败不能记作零发现。无派发能力、仅一模型、身份未知或部分失败时保留有用发现并明确降级，不宣称本轮跨模型审核完成。不擅换付费模型、提高预算或开 PR 修模型名；重试前写明可纠正原因与停止条件。

## 守住只读边界

宿主支持权限限制时使用只读权限，并记录实际限制；提示词只读不等于系统已强制沙箱。必要最小证明仅在已有授权允许的隔离临时位置执行并留证，不修改被审源码，不影响共享实例，不访问未授权生产环境。严格只读或不可执行时仅做静态检查并标为待证。

## 主审核实与裁决

主审读取原始报告，按根因和触发路径归并，保留来源、分歧及每条发现的去向。核对调用链与输入约束，区分实际运行、源码推导和待证；必要时按上述边界用真实代码证明。需要追踪跨边界假设时可复用包内 [blast-radius](../blast-radius/SKILL.md)，缺失不影响基本审核。

模型赞同数只是线索，不是证明。单个模型的充分证据也可阻塞；共同误报仍应排除。遵守项目已有规则，不把个人写法偏好、固定文件行数或重构欲望当作新增阻塞门槛。

按证据裁决为：应修复、待权衡、仅记录、已排除；逐条保留理由，需补验证的问题明确标出。不要为了栏目填充发现，也不要按人数投票给出 approve。

最终简短交付意图、范围与快照、实际审阅者及失败项、发现与裁决理由、证据位置和未验证范围。审核不能替代 verify 的真实用户路径验收。
