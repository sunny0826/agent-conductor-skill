# 追上这次对话

说明用户上次自己写下的消息之后，这次对话里发生了什么。通知和子代理回报不是用户的消息。假定用户记得那条消息，之后的内容都不记得。

用 [bro](../bro/SKILL.md) 的口气，不重述上一条回答。说用户能感到的变化，不说你怎么做的。说“测试通过”，不说“CI 绿了”。除非用户要靠它行动，否则不写哈希、路径、命令、构建号和测试数量。PR、分支和代理用用户认得的名字。一个事实需要上下文才成立时，补上上下文，否则删掉。

## 收集

收集和说明进度的阶段只读，不为补摘要改代码、启动应用或任务、发布内容。图只能来自已有材料。用户在已授权任务中询问进度，回答后继续原任务；用户明确暂停或只要求摘要时停止。收集你自己的工作、子代理报告和这段对话里其他人的消息。核对这次对话碰到的每个 PR、检查或代理的当前状态。每个要展示的数字都对回来源，改过就说改过。

行动项是只有用户能做的决定或步骤：产品选择、批准、不可逆操作，或你没有的权限。用户上次消息之前就在等的也算。你自己还能做的不是行动项。不为了填回复编造决定。用户没要求、工作也不需要的步骤不是行动项；只有它不可逆且正在等用户时，写一行，不配图，不写用户不回答会怎样。

## 回复

正文保持几句白话，以一眼能读完为准，不对中文机械计词。比句子更容易看懂时才画：设计或系统怎么连、带状态的 PR 栈或依赖、修复前后、选项并排。不画状态清单，不画互不相连的方框。同一事实不在文字和图里重复。对用户没有变化的工作不写。字不够时先砍经过，再砍行动项。

开头一句：有几件事等用户，或没有。什么都没发生、也没有事在等，就结束摘要；原任务是否继续按用户指令判断。

先放已经有的截图和视频，再放能解释变化的图。然后每个用户要求的事项一行：结果是什么，以及完成、还在跑、失败或没检查。像口头说：“搜索慢是因为缺索引”，不说“搜索审查：完成”。顺手发现并修掉的缺陷要提名。单独读这一行也必须成立。还在等用户的不能标完成，行动项里的内容这里不重复。摘要下最多三行，只写会改变用户所知或所做的事。再用一行说出你自己还能做的剩余工作。

行动项用普通列表，不用图或方框。每项两行；用户没要求的不可逆步骤一行：决定、你的建议和原因，然后用户不回答会怎样。问的是用户拥有的决定，例如合并、批准或挑选。你本来会先做的步骤、必须先发生的事、不能撤销的事，写进建议。不知道就写“未知”，并链到已有细节。

列表后给出选择。上面的截图已经展示选项时，在图下写收益和代价，不再画新图；否则把选项并排，有现状就放上现状。每个被权衡过的选项都写得到什么、付出什么，正文其他地方不再重复。

## 图

图是截图、视频、Mermaid、已有的图表或已生成的图片。带前后列的 Markdown 表格不是图。

每张图一眼能读完，按终端或页面宽度减少框数和标签长度。标签用口头的话，不用“测试：通过”这种标记。需要一句话的事实放进正文，或删掉。

看得见的变化用已有截图或视频说明：宿主支持且分享授权允许时嵌入，否则给可点击的产物路径或链接并简述变化。不为摘要自动上传媒体。没有截图时，摘要行写“还没有截图”，并说明屏幕上变了什么。图和数字只来自已有事实。不编造数字，不画或生成没拍到的屏幕。只链接真实存在的产物。
