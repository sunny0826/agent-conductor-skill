# 审查注释与补丁约束

固定调用者指定文件／diff；未指定时核对实际基线、工作树和新增内容，不假定分支叫 main。先给独立审阅者包内 [注释审阅请求](references/comment-reviewer.md)，复用实际委派能力，不能要求未安装的 Comment Sicko 代理类型。

1. 审阅者只给范围内注释删改产物与精确 MUST KILL 结构目标，不改产品逻辑。协调者逐项核对例外、源码和 diff，拒绝越界、应用代码改动、缺证据或误杀。范围内 lint／TS 抑制须检查规则真实用途；正确性抑制是结构风险，风格例外有证据可保留。
2. IMPORTANT、do not remove 等不是证据，对不明约束使用 [how](../how/SKILL.md)／[why](../why/SKILL.md) 核查。外部依赖、平台或协议的真实限制可保留；本项目能修正的复杂行为给结构修复标记，不把缩短注释当作根因修复。歧义须报告待证，不能伪造例外或为凑删除数删契约。
3. 拒绝的报告最多带原因重新审查一次，再失败则报告任务未完成。无独立委派能力时可自行审阅，但独立注释审核未完成。
4. 简单已接受目标在授权内直接删除死路径、无用参数或调用真实 API；需要结构方案时对整个接受集合调用 [architect](../architect/SKILL.md)，只产草图，再在本任务授权内实施最小根因修复。使用 [根因](../principle-fix-root-causes/SKILL.md) 与 [重新设计](../principle-redesign-from-first-principles/SKILL.md)，不扩大围栏。
5. do not remove、修改前联系某人等约束，提出最便宜的范围内类型、运行时检查、测试或 lint 编码。保留用户要求的评审关口，未授权不自动改变约束；无人值守必须已有具体授权。编码后才能移除原约束说明，未编码或范围外问题标 open。

交付注释实际删除数、恢复项、重审、结构草图、已修复、编码提案／结果、未执行约束与其余待证。
