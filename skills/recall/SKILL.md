# 恢复最近工作上下文

先区分跨会话上下文恢复、某个具体会话接手和习惯提取。已有完整状态包时直接使用并核对，不重复挖掘。具体接手见 [session-pickup](../rigor/playbooks/session-pickup.md)，习惯提取见 [automate-me](../automate-me/SKILL.md)。

1. 固定主题、工作区和时间窗；默认最近 7 天，用户指定“全部”不能偷偷缩成最近若干。只使用宿主明确提供的本工作区历史接口／转录路径，不推算 Cursor 私有路径或扫描其他项目。
2. 对少量会话直接检索；大量历史在授权委派可用时按时间片分工，用真实时间而非 UUID 排序，先匹配主题再读相关段落。排除本次会话和测试噪声，返回用户目标、决定、未解项、纠正及 PR／分支等产物，每项有会话 ID 或证据指针。
3. 主题涉及功能、文件、系统或错误时使用 [why](../why/SKILL.md) 的来源方法调查共享记录，但把问题设为“当前状态、尝试与回退、仍在报告的症状”。与本人的历史共同核对，缺来源如实记录。纯活动回顾无具体目标可省共享调查。
4. 使用实际可用的 Git／源码工具核对分支、PR 和工单当前状态；旧聊天说已合并不证明现在已合并。结论依赖代理具体动作时读范围内原转录，摘要不足则标缺口。
5. 用 [unslop](../unslop/SKILL.md) 交付简短状态包：至多五项概览；各线程一行注明 merged、open PR、in flight、verified-uncommitted、reverted、planned 或明确 unknown；至多五项重复问题与失败尝试；一个最有用的下一步。引用真实记录，不能伪造 PR 号或状态标签。

查无历史时交付有界当前状态与缺口。对外展示前去除无关私密材料。回顾本身不授权继续实施、发送消息或修改记录。
