# 复现并修复错误

1. 亲自在 [真实表面](../references/verification-surfaces.md) 复现，先推进能操作的部分；确实够不到目标才带具体理由请求用户补信息。合成触发或加授权内诊断必须标明条件，不冒充原场景。
2. 用 [how](../../how/SKILL.md) 和相关 [why](../../why/SKILL.md) 建立候选根因，选择能排除最多假设的实验，必要时运行诊断。确认机制再定修复，源码猜测不能称实证。
3. 需要结构改变先 [architect](../../architect/SKILL.md)。有实际授权委派才按具体文件与完成条件分工，否则主会话完成并标独立性限制。
4. 在同一表面重跑原复现；不确定或不同表面不是通过。便宜检查用 [tdd](../../tdd/SKILL.md)，昂贵／不清检查用有效替代。
5. 仅保留证据支持的最小改动，反证后撤回本轮动机对应改动。保留失败后通过输出和实际版本。已有提交授权时按失败复现、修复的可复核顺序组织历史；需要 PR 且已授权才进 [Opening](opening-a-pr.md)。
交付错误、根因、修复、验证、原始失败／通过及缺口。
