# 实现新行为

1. [how](../../how/SKILL.md) 理解现状，非机械结构用 [architect](../../architect/SKILL.md) 比较，先定领域数据形状。
2. 吞吐检查保留四项：阻塞前置、独立工作流、共享状态、最小安全分解；不适用写原因。一个耦合功能给一个拥有者，内部只在前置完成后跨独立边界展开。
3. 任务包有精确范围、类型形状、行为契约和证据。多种有效实现结构时用 [arena](../../arena/SKILL.md) 比较完整方案，有能力才实际独立评判，不用“主会话想过”冒充。
4. 最小实施，固定来源派生文件重新核对上游；共享原语变更覆盖真实消费者。在 [真实表面](../references/verification-surfaces.md) 证明新行为和旧契约，分单元验证。
5. 有争议设计需要 [interrogate](../../interrogate/SKILL.md) 压力审核；记录失效独立阶段。只在已有授权下组织提交／[PR](opening-a-pr.md)。
交付用户行为、结构选择和理由、吞吐检查、验证与开放决定。
