# 设计可审计的执行流程

适用复杂迁移、跨范围调整或多部分变更，且没有更窄的现有流程可直接套用时。先阅读适用的 [原则清单](../references/principles.md)，建立待办，先交付可评审的执行阶段设计与验证方案，再按阶段门和产物推进。

1. **定义完成条件与强度**：写明可证伪的完成条件、单元数与粗略工作量，核对前置阻塞。按单向决策与影响范围提高证明强度，可逆小步骤保持轻量。先说明长任务的范围与取舍，保留用户指定关口；仅在既有持续授权内自主推进。
2. **拆分为可验证单元**：按依赖拆出可独立验证的单元，最不确定的风险先做，先捕获改动前基线并建立必要验证与脚手架。非机械结构决策使用 `architect`（已定方案不重复比较）。并行只跨清晰边界，写者各自隔离，遵守 [先分离再串行化共享状态](../references/principles.md#先分离再串行化共享状态)。把阶段与每步检查写入待办。
3. **写假设并逐单元实证**：每个单元写明假设、做最小改变并核验真实产物；推进目标的保留，无收益仅撤回本轮拥有改动。按 [逐单元验证与计划迁移](../references/principles.md#逐单元验证与计划迁移) 推进；委派结果由协调者亲自核对，检查被迎合则收紧契约，检查本身错误先修检查。结果记为 `VERIFIED`、`NOT VERIFIED` 或 `INCONCLUSIVE`，后两者均不算通过。
4. **保留决策轨迹**：全程在任务状态或只追加工作记录中保留时间、阶段、决定、原因、证据路径与结果，不在最后补造历史；只有已有提交授权时才提交轨迹文件。
5. **收口整体验证**：最后对真实产品重新核对最初完成条件与组合后的整体行为；重复纠正优先编码进结构或检查。交付阶段设计、强度理由、轨迹位置、已证明与未完成范围。持续唤醒只依赖宿主真实事件或定时能力，不用一次性执行冒充长期流程。
