# 围绕一个指标持续改进

1. 用 [how](../../how/SKILL.md) 建模真实工作量维度，找到重现用户症状的场景，否则先修复复现。固定指标、优劣方向、目标和最少尝试次数的停止条件，不自行弱化用户数值。
2. 做可复跑 harness，用轻／重真实负载证明灵敏度，经 [benchmark-checklist](../../benchmark-checklist/SKILL.md) 核验后冻结；输出错误与真实工作计数，记录足以区分噪声的基线和正确性回归 gate。
3. 用 [决策日志](../../show-me-your-work/SKILL.md) 每次记假设、变更、前后指标、门槛、保留／撤回及证据，额外测量表作证据链接，不另造冲突日志格式。
4. 假设对应具体机制，按 [Perf](perf-issue.md) 的优先顺序探索，但不借用一次修复的停止条件。独立实验各自隔离，协调者核验真实 diff。
5. 一次一个变更，同一冻结 harness 测前后并跑回归；只有超过噪声且行为正确才保留，其他仅撤回本轮拥有改动。每次验证结束才下一次；已有授权才每个接受结果提交。
6. 连续拒绝或平台期换类别、重读来源、组合已知机制，不堆未测试改变。行为和简单性高于数字，可保留不损指标的结构简化。目标达成或真正没有值得成本的假设才结束；未达目标明确状态，不降低标准。
7. 交付指标／目标、基线到最终、尝试与接受／撤回次数、各有效修复、日志和下一条值得尝试的思路。真实唤醒能力借 [Autonomous](autonomous-run.md)，不改本流程的停止条件。
