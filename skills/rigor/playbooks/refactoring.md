# 保持行为的结构调整

1. 用 [how](../../how/SKILL.md) 固定真实行为契约，移动前保存特征测试、快照或等价基线，类型检查不是行为 pin。
2. 明确缺失领域结构与今日目标形状，方案应减少分支、无效状态或读者负担而非加透传；非机械边界变更用 [architect](../../architect/SKILL.md)。
3. 先删除本轮冗余再改结构，分小步骤始终让 pin 通过。满足无外部兼容承诺与协调迁移条件才按 [迁移原则](../../principle-migrate-callers-then-delete-legacy-apis/SKILL.md) 同轮迁移并删除旧 API。
4. 逐个核对字符串、文档和反向引用中的真实调用者，机械编辑可按实际能力委派。真实旧新输出／重放证明等价，编译不够。
5. 新错误或新功能另分任务，不偷偷改行为。收益要能说明读者负担减少，无收益撤回本轮改动；已有授权才按先减后改组织 [PR](opening-a-pr.md)。
交付结构、pin、等价证明、可读性收益与保留／撤回内容。大范围用 figure-it-out。
