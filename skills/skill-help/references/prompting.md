# 提示指引

写目标和可通过／失败的完成条件，附已知症状、复现、日志、真实链接及边界。要证据就说明命令结果、用户流程、读回状态或公平前后测量。不要把猜测说成根因，不以时长代替完成。

上下文缺失可请求范围内回顾；陌生系统先调查，不把讲解当实施授权。结构选择用可观察原型／源码约束减少假设，保留真实产品偏好由用户决定。已经清楚的任务用“继续”即可，换主题明确新任务。

无人值守写完成检查、可操作范围、停止条件、证据与是否已有提交／发布授权，宿主无持续工具不能承诺循环。用户需要 review checkpoint 时明确保留。只给与当前问题相关的一个提示，不做固定问题问卷。

需要可直接复制的用法时，按 [提示示例](recipes.md) 选择对应场景，包括通用审查、PR 状态、持续执行、个人模式和 webhook 页面。
