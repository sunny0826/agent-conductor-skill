# 可适配的提示示例

- 复述：“用自己的话说明我的目标和要解决的问题，先不要做。”
- 收紧：“按专家做法收紧这个任务，保留一个能判断对错的外部检查，然后直接做。”
- 追上：“用 ketchup 说明我上次发言之后变了什么，只列我必须做的决定。”
- 理解：“用 how 解释这个入口到结果的路径，只调查，不改代码。”
- 回归：“复现这个错误；测试便宜时用 tdd，保留修复前失败和修复后结果。”
- 设计：“比较结构方案，先给接口和归属，等我看过再实施。”
- 验收：“检查这次改动影响的用户入口，保留真实操作和清理后证据。”
- 计划：“将这个已定设计拆成小的可验证单元，只输出计划。”
- 复盘：“按本次会话证据提炼可改变后续决策的技能改进，先给提案。”

名称仅是示例，实际调用按宿主支持和包内文件路径。提示内容不创造提交、外部发送或生产操作授权。

## 不依赖特定编辑器的提示模式

下列提示可直接发送给当前 Agent。把尖括号替换成真实对象；宿主未注册技能时，明确要求读取对应链接中的文件。

| 场景与说明位置 | 可复制的提示 |
|---|---|
| 界面截图：[control-ui](../../control-ui/SKILL.md) | 用 control-ui 在 `<实际应用／页面>` 验证 `<用户路径>`，交付关键操作前后的截图，读回确认内容和用户可访问性，说明观察结果及未验证项。 |
| 代码审查：[代码检查](../../rigor/references/code-review.md) | 只读审查 `<base..head>`，结合实际调用者查找可证明的缺陷。每项给出位置、触发条件、影响和证据；说明未验证范围。不要修改代码或发布评论。 |
| 核实已有意见：[审查意见核实](../../rigor/references/review-triage.md)、[计划清单](../../rigor/assets/plan-template.md) | 核实 `<PR 或意见文件>` 的审查意见，按当前 head 逐项判断修复、驳回或待确认，并给源码证据。没有意见时如实说明。先交付本地结论，不回复或关闭外部讨论。 |
| PR 状态：[Babysit](../../rigor/playbooks/babysit.md) | 对 `<PR>` 执行一次 check：核对当前 head、CI、审批和阻塞讨论，列出首个真实失败及下一步。不要持续轮询或合并。 |
| 持续执行：[Autonomous run](../../rigor/playbooks/autonomous-run.md) | 在 `<范围>` 内持续推进，直到 `<可验证完成条件>`。每轮保留证据，遇到 `<停止条件>` 时停止。只用实际可用的持续运行能力；无法跨轮唤醒时，完成当前能做的工作并给出恢复提示。 |
| 多任务恢复：[Orchestrate](../../rigor/playbooks/orchestrate.md) | 接手 `<计划及状态目录>`，核对每项产物、本地进程和远程会话的实际状态，再决定续接或重新派发。沿用原范围和预算，不从本地退出推断远程已结束。 |
| 个人模式：[automate-me](../../automate-me/SKILL.md)、[rigor](../../rigor/SKILL.md) | 用 automate-me 把 `<工作偏好>` 写成项目技能，沿用当前宿主支持的位置，明确触发范围并给出调用方式。不假定它会自动常驻或影响其他会话。 |
| 技能位置：[create-verification-skill](../../create-verification-skill/SKILL.md) | 为 `<项目>` 创建验收技能并实跑一个用户功能。使用项目已有且宿主能发现的技能位置；无自动发现能力时给出文件引用方式。 |
| 历史回顾：[recall](../../recall/SKILL.md) | 用 recall 回顾 `<项目／主题>` 在 `<时间范围>` 内的决定和未完成事项，只读取明确可用且属于该范围的历史接口，并核对当前状态。 |
