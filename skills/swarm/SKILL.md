# 并行覆盖与竞赛

开始建立 Frame、Fan-out、Aggregate、Report 待办。

1. 固定完成条件和产物，选择分片覆盖、相同任务竞赛或混合。竞赛在派发前声明 first pass、rank all 或 best-of，不能见结果后换规则。N 是总工作者数，不是并发上限，按宿主容量分批。
2. 复用宿主或用户实际模型选择，必要时使用包内 [setup](../agent-conductor-setup/SKILL.md)，不编造云环境、模型或默认回退。每个写者独立目录／worktree，度量和验收任务固定精确版本、样本定义、次数、顺序和方法。
3. 有实际委派能力才派发，任务包完整包含目标、范围、独立切片／竞赛臂、输入、权限、验证、输出位置及 PASS／ISSUES／BLOCKED 契约。必须指出所有能证明的问题，不只报第一个；证据共享时避免把其他工作者答案传给首轮竞赛。
4. 只针对真实活动句柄等待并收集终态，失败或退出不算零问题。版本或测量方法缺失的结果退回一次，第二次仍缺标为 gap，不无限重跑。覆盖模式每个必需切片都有结果才完整；竞赛用原定规则。校验真实产物，不直接转发自述。
5. 汇总简表、带证据的问题、缺片／退出与竞赛规则。没有委派能力可自行分片检查，但报告并行 Swarm 未完成；同模型多会话不叫跨模型。

写入归属遵守 [隔离原则](../principle-separate-before-serializing-shared-state/SKILL.md)。任务不自动授权发布、消息发送、全局配置或合并。
