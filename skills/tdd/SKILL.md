# TDD · 先复现，再修复

目标是让错误行为可执行：先证明检查会因目标错误失败，再修复实现并证明同一检查通过。本技能独立使用，不依赖其他 SKILL、模型配置或多代理。

## 选择可行的回归路径

明确预期行为、当前行为、影响路径和最小可观察复现。优先使用该代码路径已有的单元、组件、集成或回归测试，选择最窄且能检验真实行为的入口。

需要大规模 harness、脆弱 mock、慢速端到端环境、仅生产可见状态、模糊复现或大量无关 fixture 时，不强行新增测试。使用最接近的有效验证：定向脚本、手动复现命令、浏览器操作、快照比较、日志断言或已有集成检查。工具按当前项目和宿主能力选择，不为套用流程引入新框架。

## 先失败，再通过

1. 在修改产品实现前，编写能捕获该错误的最小检查。断言预期行为，不镜像实现细节。
2. 对未修复实现运行检查，保留命令、版本、输出和退出状态。确认失败确实来自目标错误；检查已通过、依赖缺失、导入失败或环境错误，都不能充当复现成功。
3. 检查不成立时，先修正复现或测试，再动实现。无法取得目标失败证据时明确说明，不伪称已完成“先失败”。
4. 在已授权范围内最小修复产品，保持附近契约，保护用户已有改动。
5. 对修复后实现运行同一检查，保留通过证据。按影响范围执行必要的附近验证，不把单个回归通过称为整体验收。

## 守住测试含义

- 不为迎合错误实现修改预期或削弱断言；预期确实改变时说明依据。
- 优先没有新测试，而不是主要验证 mock、依赖时序、复制内部结构或需要无关环境的坏测试。
- 不扩成无关测试覆盖或重构；发现一类问题时，先证明并修复当前路径，再按实际需要考虑相邻覆盖。
- 偶发错误尽量取得确定性复现，记录所固定的信号；无法稳定复现则保留限制。
- 替代验证同样记录实际观察。严格只读或无执行条件时说明未运行；不制造测试数据来冒充实际错误。

交付修复前失败的检查与原因、修复后同一检查的结果、附近验证与证据位置。未取得失败证据或使用替代验证时明确标注原因和覆盖范围。调用本技能不自动授权提交、推送或发布。
