# 写清楚技术文档

目标是让疲惫的读者第一次就能理解。先删无信息文字，用短而准确的词；规则让句子变差就换方法或保留原句。源码中的符号、路径、参数和命令是权威词表，不发明同义术语。使用包内 [unslop](../unslop/SKILL.md) 清理套话，不自动修改该技能。

## 先确定文档目的

用“行动／理解”和“学习／工作”选择 Diátaxis 模式：

- 教程：学习者实际做出一个结果，每步有可观察输出。告诉读者将构建什么，必要背景短写并链接，不让长解释打断步骤。
- 操作指南：解决具体目标，假定读者已有必要能力，给条件分支和动作，标题以目标命名，不凑完整百科。
- 参考：可查找的真实事实、选项、错误和限制，结构贴合被描述对象，不混入说服或教学。资料未获证时明确未知，不用肯定语气掩盖缺口。
- 解释：一个有边界的“为什么”问题，说明历史、约束、取舍和替代，判断要有依据。

一个页面以一个目的为主，其他模式分开或明确链接，不把教程、参数表与辩论混在同一段。短 PR／提交说明应用下面句子原则，不为它们强套四类文档。

## 对读者写句子

优先现在时、明确执行者和直接动作。条件写在受其约束的步骤前，常见路径先于例外。读者称呼按语言与项目约定，不写“只需”“很简单”弱化真实成本。链接文字说明目的地，标题承载信息，标题层级连续。

顺序用编号，其余平行项用项目符号；清单前有完整引导句。代码与符号用代码格式，UI 文案按既有格式，不用“等等”隐藏未说明范围。不要预告没有依据的未来能力。

每句话一项动作或一个完整想法，长短句自然变化。英语可用约 20／25 词提醒动作句／说明句过长，中文不机械数英文词。解释可表达有证据的观点，参考保持客观；不为短句删掉必要语法和条件。

## 消除歧义

统一每个概念的名称、每个词的含义。“仅”“不”“和／或”靠近其作用对象，多个对象的连接关系写明确。指代必须唯一，长名词串拆开，重复主体和必要冠词好过让读者猜。避免删动词、省略名词或用斜线替代真实逻辑；数学、路径、代码和逐字引用保留原字符。

优先主动语态；执行者未知或不重要则允许被动，不捏造责任者。避免习语、修辞和无意义副词，单位与数值保留。括号有必要且内容完整时可保留，不机械套用英文标点禁令。

PR 描述先说具体问题和结果，用一项主数字而非原始日志／SHA 清单，证据链接到实际已读产物。产品 UI 字符串使用产品自己的文案规则，不把技术文档标准强加过去。

示例使用真实名称和与项目一致的缩进，不强制所有代码用 tab。目录树、数量与当前版本必须相符，提供实际可重算的方法。最终复核目的、技术事实、证据强度与歧义，只改授权文件。
